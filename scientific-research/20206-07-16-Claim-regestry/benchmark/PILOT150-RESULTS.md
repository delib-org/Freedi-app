# Pilot-150 replication on the current production model (2026-08-24)

Re-runs the registry conditions on the fixed 150-triplet stratified pilot
(`results/pilot-ids.json`, seeded sample of the 875 Blair–Procaccia–Tambe hard
triplets) with the production stack as of today: `WORKER_MODEL = gpt-5.6-luna`
(the 2026-08-17 model upgrade), current `CLASSIFY_SYSTEM` (incl. Phase-0b
stance caution), canonicals regenerated by the current model (old
`generated-claims.jsonl` set aside as `generated-claims-4omini.jsonl`).
Runner: `run-registry-single.ts --sample results/pilot-ids.json [--enriched]
--tag "-pilot150-luna"`. Analysis: `analyze-pilot150.py`. Attach rule unchanged
(expresses ∧ confidence ≥ 0.6); correct iff match attaches ∧ distractor does not.

## Findings

1. **Raw-anchor registry is robust across model generations.** 96.7% on
   gpt-5.6-luna vs 98.7% on gpt-4o-mini, statistically indistinguishable, and
   far above the paper's DPT (80.0% on the full set).
2. **The enriched condition regressed to DPT parity — and the failure is
   canonicalization, again.** All inspected false-attaches (15) are cases where
   the luna-generated canonical *dropped the anchor's stance qualifier* (e.g.
   an illegal-with-life-exception anchor canonicalized as "Abortion is
   permitted when pregnancy poses a genuine risk to the mother's life"), so the
   classifier correctly matched the stance-flipped distractor to a stance-lossy
   claim. The 19 missed matches are the reasoning model refusing over
   sub-distinctions ("health" vs "life", category vs instance) against
   compressed canonicals. Same weak link as the B1→B2 gap in the full run
   (−24.9pp), now with a model-sensitivity dimension: **enriched-registry
   accuracy is a property of the canonicalization model, not of the
   architecture, and must be regression-tested on every model upgrade.**
3. **Operational: `maxTokens: 300` starves gpt-5-family output.** For
   `gpt-5.*`, `buildModelParams` maps `maxTokens` to `max_completion_tokens`,
   which *includes reasoning tokens*. On 2/150 inputs (both long abortion-topic
   GSC statements, `main:537`, `main:708`) the model deterministically spends
   the whole budget reasoning and returns empty content → JSON parse error →
   fail-closed, surviving all harness retries. Excluded as hard errors per the
   harness protocol (B2E n=148). Production fix indicated: raise the
   classification completion cap for reasoning models.

## Fix round (same day)

Two production fixes were applied and the pilot re-run under tag
`-pilot150-luna-fixed` (canonicals regenerated under the new prompt; old luna
cache set aside as `generated-claims-luna-prefix.jsonl`):

1. `openai-chat.ts` — `buildModelParams` reserves `REASONING_HEADROOM_TOKENS =
   2000` on top of the caller's `maxTokens` for `gpt-5.*`, so hidden reasoning
   can no longer consume the whole completion cap.
2. `claim-registry-service.ts` — `GENERATE_SYSTEM` no longer asks for a
   "neutral" claim (read as *stance*-neutral); it now requires the claim to
   carry the author's stance, direction, and defining conditions, with the
   observed inversion spelled out as a counter-example, and allows up to 20
   words when brevity fights stance fidelity.

| Condition | Model | Triplet acc. [Wilson 95] | Match recall | Distractor false-attach |
|---|---|---|---|---|
| FIXED B1 (raw anchor, headroom) | gpt-5.6-luna | **98.0% [94.3, 99.3]** | 98.0% | 0.7% |
| FIXED B2E (enriched, stance-preserving canonicals) | gpt-5.6-luna | **82.7% [75.8, 87.9]** (n=150) | 90.7% | 9.3% |

McNemar: NEW B1 vs FIXED B1: 0 vs 2, p = 0.5 (2 gains, zero losses). NEW B2E
vs FIXED B2E: 5 vs 10, p = 0.30 (directional gain, not significant). Old B2E2
(4o-mini) vs FIXED B2E: 17 vs 3, p = 0.0026 (still below the old model).

**Outcome.** The headroom fix is a complete success: both runs finish 150/150,
the two deterministic empty-content failures are gone, and raw-anchor accuracy
ticks up to 98.0% with strictly no regressions. The stance-prompt fix is a
partial success: recall recovered (+3.5pp) and the canonical texts now carry
stance (e.g. "Abortion should be prohibited except when the mother's life is
truly at risk" — previously inverted), but false-attaches barely moved.
Inspection of the residual 14 shows two mechanisms the prompt cannot fix:
(a) **compression loss on multi-part opinions** — a long statement making
several points compresses to one claim, and when the kept point is the
stance-shared or secondary one ("abortion policy should address racial
disparities"), the stance-flipped rewrite genuinely expresses it too; and
(b) **a more charitable reasoning-model classifier** that accepts partial
matches against enriched lines ("the added comment does not oppose that
exception") where gpt-4o-mini answered none.

**Architectural conclusion.** Compressive canonicalisation is inherently lossy
for long multi-issue statements; no prompt closes the gap. The robust
configuration on the current model is raw-anchor matching (98.0%): keep the
generated canonical for *display*, but weight the verbatim exemplar/anchor as
the operative matching text.

## Caveats

- The pilot slice is *easier* than the full set (old B1: 98.7% on pilot vs
  95.0% on 875). Old-vs-new contrasts on identical triplets are the valid
  comparison; pilot absolutes should not be quoted against full-875 numbers,
  including the paper's 80.0%, without this caveat.
- The paper's per-triplet predictions are not available, so DPT could not be
  restricted to the same 150 ids; on this easier slice DPT would plausibly
  score somewhat above 80%.
